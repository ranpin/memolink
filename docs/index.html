Q1–Q5 闸门全部在 Orin 真机跑通：五操作消解（Q2）、类型特化检索（Q3，v2 基准 +31.2pp）、受约束提取（Q4，编造率 3.7%）、LongMemEval 英文模型 config-only swap（Q5，dim 384，5/5 验证）。详见 docs/memory_v2_design.md。

诚实边界

  1. System-1 覆盖率实测 ≈32%（非设计文档声称的 70–80%）——新颖度信号无法区分 UPDATE/SUPERSEDE/REINFORCE，矛盾是语义量，故模糊地带必须交给 System-2 本地 LLM。
  2. 类型特化检索的收益是有条件的：v1 基准饱和（+0），v2 基准 +31.2pp——不是普适提升，取决于语料是否可分。
  3. 提取编造率 3.7% 是上界，多为改写非捏造；受约束 JSON 输出规避了 P2 实测的开放式生成编造。
  4. 检索评测与 LLM 生成解耦：本项目只评测记忆检索/消解质量，不含生成质量评测。
  5. embedding 走 CPU（onnxruntime 在 Orin 上是 CPU-only），GPU 整块留给 LLM；单设备、未测热降频与功耗。

复现

sudo apt install -y libsqlite3-dev libcurl4-openssl-dev libjsoncpp-dev
# config.ini 的 [edge] 段填 model_quantized.onnx 与 tokenizer.json 路径
# config.ini 的 local_url 填本地 llama-server 地址（如 http://127.0.0.1:8099）
mkdir build && cd build
cmake .. -DMIRIX_ENABLE_EDGE=ON && make -j8 mirix-mem
./mirix-mem ingest "用户喜欢深蓝色的车" --type semantic
./mirix-mem recall "我的车是什么颜色偏好" --top 3

代码与完整文档见 github.com/ranpin/mirix-cpp。记忆分层架构参考自 Mirix-AI/MIRIX（Apache-2.0）。
