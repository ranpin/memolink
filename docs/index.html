架构

┌──────────────────── Jetson Orin（全程离线）────────────────────┐
│                                                                │
│  写入 write(type, content, sensitive)                          │
│    └─ WordPiece 分词 → ONNX INT8 编码 → recall_memory 落库      │
│       → saveEmbedding → 分类型 FIFO 淘汰                        │
│                                                                │
│  检索 retrieve(query, topK)                                    │
│    └─ 编码查询 → searchByEmbedding（暴力余弦）→ 重算分数 → 排序  │
│                                                                │
│  存储：SQLite（recall_memory 带 embedding BLOB）                │
│  编排：MemoryOrchestrator（原为 4 个空壳，本项目填实）           │
└────────────────────────────────────────────────────────────────┘

记忆类型存进 message_type、敏感标记存进 metadata，从而复用 mirix-cpp 原有的 ~2,600 行记忆存储层（manager / StorageManager / InitDB schema），未改动。

端侧三件套（本项目新写）

① C++ WordPiece 分词器

src/models/WordPieceTokenizer

自写 UTF-8 解码 + BertNormalizer + BertPreTokenizer + WordPiece 贪心，配置读自 tokenizer.json。不依赖 Rust tokenizers。与 HF 逐 token 对拍 25/25 一致。

② ONNX Runtime C++ 推理

src/models/OnnxEmbedder

onnxruntime 原生 C++ API（pImpl 隔离头），跑 bge-small-zh INT8。CPU-only——刻意把 GPU 整块留给 LLM。FP32 对拍 Python 余弦 1.00000000。

③ 记忆编排器

src/database/managers/MemoryOrchestrator

原为 4 个空壳（return true/""）。填实为：按类型写入 + 跨类型检索合并 + 实时写入 + 分类型有界 FIFO 淘汰 + 敏感标记传播。

INT8 vs FP32：量化对检索的影响

F1 只测了 embedding 余弦（0.99），没测排序会不会翻转。这里直接比 top-k 命中集合。

域顺序完全一致集合一致recall/MRR/hit@1
cockpit10/1511/15完全相同
robot11/1513/15完全相同
av6/1510/15完全相同

结论：聚合指标完全相同，expected id 的排名不变（hit@1 全同）；差异只出现在 top-k 尾部（rank 3-4 的无关项）——这些项本来相似度就接近，INT8 的微小扰动会翻转它们的顺序，但不影响检索质量。

诚实边界

  1. 语料与标注均由本人手写，GT 是自定义的——证明的是「检索能按语义找回该找回的」，不是与公开基准对比。
  2. 检索评测与 LLM 生成解耦：本项目只评测记忆检索质量，不含生成质量评测。
  3. embedding 走 CPU（onnxruntime 在 Orin 上是 CPU-only），未测 GPU embedding。
  4. INT8 量化来自 onnx-community 的预量化模型，非本项目量化。
  5. 单设备、未测热降频与功耗；数字是冷启动/短负载下的。

复现

sudo apt install -y libsqlite3-dev libcurl4-openssl-dev libjsoncpp-dev
# config.ini 的 [edge] 段填上 model_quantized.onnx 与 tokenizer.json 路径
mkdir build && cd build
cmake .. -DMIRIX_ENABLE_EDGE=ON && make -j8 test_retrieval_eval
./test_retrieval_eval ../bench/corpus/cockpit.json ../bench/eval/cockpit_eval.json eval.db out.json 4
