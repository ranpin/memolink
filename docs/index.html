结论：agent 记忆的现实量级是 1e3~1e4 且增量更新——精确检索亚毫秒、recall 恒 1.0、建索引近乎免费、追加 O(1)；HNSW 在 10 万条上建索引要 36s，换来的查询加速却发生在本就不是瓶颈的环节（生成 ~920ms vs 检索 0.16ms）。故 memolink 刻意用精确检索（SQLite 暴力余弦），ANN 在此量级是过度设计。embedding 侧：INT8 相对 FP32 余弦 0.99+、单线程比 FP32 双线程还快、模型 23.9MB vs 94.8MB——佐证 memolink 的 ONNX INT8 embedding 选择。

核心方法

记忆生命周期全程在本地完成：提取 → 消解 → 存储 → 检索 → 更新 → 删除 → 版本回溯。座舱域天然把这些机制变成「看得见、且非它不可」的功能——而不是一个套了记忆库的聊天机器人。细节见 docs/memory_v2_design.md（含诚实边界与复现）。

机制做法
双过程消解System-1 确定性规则（空库/无同类型→CREATE、逐字重复→REINFORCE）处理约 32%；相似度落入模糊地带的交给 System-2 本地 4B LLM 五分类（CREATE/UPDATE/REINFORCE/SUPERSEDE/NOOP）
类型特化检索查询意图路由 + 同类型加权（×1.6）+ 时间衰减——v2 基准 hit@1 +31.2pp（episodic 3/8→8/8）。「上次充电在哪」路由到 episodic、「座椅加热怎么开」路由到 procedural，不是全类型一锅搜
非破坏性版本化SUPERSEDE 把旧值标记失效但保留，history 可回溯完整演变（Graphiti 式边失效的端侧落地）。如搬家后地址从西湖区改滨江区：旧记忆失效保留、新记忆入库建双向链
多驾驶员治理GovernanceFilter 按 owner+scope+authority 强制端侧隔离：换驾驶员后，前任的私人记忆（家庭住址、孩子学校）被拦截不可见，共享记忆（车辆电池/续航）仍可见；strict fail-closed
端侧实现C++，自写 WordPiece 分词器 + ONNX INT8 embedding（与 HF 逐 token 对拍 25/25），本地 4B LLM 做消解与提取，全程离线
