# 依赖库管理策略

## 概述

MIRIX项目采用本地依赖库管理策略，以提高项目的可移植性和简化部署过程。本文档详细说明了依赖库的组织结构、管理方法和跨平台支持策略。

## 本地依赖库结构

项目使用以下目录结构来组织不同平台的依赖库：

```
libs/
├── macos/
│   ├── include/     # macOS平台头文件
│   └── lib/         # macOS平台库文件
└── linux/
    ├── include/     # Linux平台头文件
    └── lib/         # Linux平台库文件
```

## 依赖库列表

MIRIX项目依赖以下核心库：

1. **SQLite3** - 轻量级嵌入式数据库
2. **OpenSSL** - 加密和SSL/TLS功能
3. **cURL** - 网络通信和HTTP请求
4. **JSONCPP** - JSON数据处理
5. **PortAudio** - 跨平台音频I/O
6. **Faiss** - 高效的向量相似性搜索
7. **OpenCV** - 计算机视觉和图像处理
8. **Qt5** (可选) - 图形用户界面

## 平台特定依赖

### macOS

macOS版本使用静态库和动态库的组合，以平衡性能和兼容性。系统框架（如CoreAudio）通过CMake直接链接。

### Linux

Linux版本可以使用系统提供的库，也可以使用预编译的库文件。建议使用系统包管理器安装依赖以确保最佳兼容性。

## 库文件类型

根据不同平台和库的特点，我们使用以下类型的库文件：

- **静态库 (.a)** - 提供更好的封装性和独立性
- **动态库 (.dylib/.so)** - 减少可执行文件大小，支持共享库
- **框架 (macOS)** - Apple平台特有的库组织方式

## 依赖管理工具

### CMake配置

CMakeLists.txt文件根据目标平台自动选择正确的库路径和链接选项：

```cmake
# 检测操作系统
if(APPLE)
    set(PLATFORM_NAME "macos")
else()
    set(PLATFORM_NAME "linux")
endif()

# 设置本地依赖路径
set(LOCAL_LIBS_DIR ${CMAKE_SOURCE_DIR}/libs/${PLATFORM_NAME})
set(LOCAL_INCLUDE_DIR ${LOCAL_LIBS_DIR}/include)
set(LOCAL_LIB_DIR ${LOCAL_LIBS_DIR}/lib)
```

### 构建过程

1. CMake检测目标平台
2. 根据平台选择对应的库路径
3. 配置包含目录和链接目录
4. 链接平台特定的库和框架

## 添加新依赖库

要添加新的依赖库，请遵循以下步骤：

1. 为每个支持的平台获取相应的库文件
2. 将头文件放入对应平台的`include`目录
3. 将库文件放入对应平台的`lib`目录
4. 更新CMakeLists.txt文件以包含新的库
5. 测试在所有支持的平台上构建项目

## 系统级依赖

某些依赖项可能需要系统级组件，这些组件无法包含在项目中：

- 图形系统库（如X11、Cocoa）
- 系统音频框架
- 网络协议栈

这些依赖项需要在目标系统上安装，并在CMakeLists.txt中正确配置。

## 最佳实践

1. **保持库版本一致性** - 确保所有平台使用相同版本的库
2. **定期更新依赖** - 跟随安全更新和功能改进
3. **文档化依赖关系** - 记录每个库的用途和版本信息
4. **测试跨平台兼容性** - 在所有支持的平台上验证构建和运行

## 故障排除

如果遇到链接或运行时错误，请检查：

1. 库文件是否存在于正确的平台目录中
2. 库版本是否与头文件匹配
3. 平台特定的依赖是否已正确配置
4. 系统级依赖是否已安装
