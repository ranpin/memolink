# 系统架构文档

## 概述

MIRIX系统是一个仿人类记忆的多模态数据处理框架，采用分层架构设计，实现了完整的记忆系统模型。系统能够捕获、存储和管理图像、音频、屏幕截图等多种类型的数据，并将其组织成类似人类记忆的结构。

## 整体架构

系统采用清晰的分层架构设计：

## 模块详细说明

### 1. 数据采集层 (Data Capture Layer)

负责从各种数据源捕获多模态数据：

- **摄像头捕获**：使用OpenCV捕获摄像头图像
- **音频录制**：使用PortAudio录制系统音频
- **屏幕活动跟踪**：捕获屏幕截图和用户活动
- **系统事件监控**：监控系统事件和用户行为

### 2. 数据管理层 (Data Management Layer)

负责数据的存储和管理：

- **存储管理器**：提供统一的数据存储接口
- **事务管理器**：确保数据操作的原子性和一致性
- **多模态数据管理器**：协调不同类型数据的处理

### 3. 记忆系统层 (Memory System Layer)

实现仿人类的完整记忆系统，包括以下记忆类型：

#### 3.1 短期记忆类型
- **消息记忆 (MessageMemory)**：存储对话历史和消息内容，包含 `processed` 标记用于跟踪是否已生成长期记忆
- **多模态记忆 (MultimodalMemory)**：存储图像、音频、屏幕截图等多模态数据的元信息和语义描述（优先使用多模态大模型输出）

#### 3.2 长期记忆类型
- **情景记忆 (EpisodicMemory)**：存储个人经历和事件相关信息
- **语义记忆 (SemanticMemory)**：存储概念性知识和事实信息
- **核心记忆 (CoreMemory)**：存储最基本和重要的信息块（分为 persona 和 human 两类）
- **程序记忆 (ProceduralMemory)**：存储技能和过程性知识
- **私密信息库 (SecretVault)**：存储结构化私密信息

#### 3.3 辅助机制
- **记忆溯源 (MemoryProvenance)**：记录长期记忆与消息/多模态来源的多对多关系，支持“证据溯源”
- **会话管理 (Session)**：跟踪用户会话，将消息与记忆按会话组织

**记忆生成流程**：
1. 消息记忆和多模态记忆作为“原材料”存储
2. MemoryGenerationManager 周期性收集未处理的消息和多模态数据
3. MemoryClassifier 判断是否生成情景、语义、核心等长期记忆
4. 对应的 Generator （如 EpisodicMemoryGenerator）生成长期记忆
5. 通过 MemoryProvenance 记录每条长期记忆的来源（消息 + 多模态）
6. 将消息标记为 `processed=true`

**配置驱动**：记忆生成行为通过 `config.ini` 的 `[memory_generation]` 节控制，包括生成阈值、最大来源数、各类记忆开关等。

每种记忆类型都有专门的管理器和数据表进行管理。详见 [memory.md](file:///Users/ranpin/code/mirix-cpp/docs/memory.md)。

### 4. 模型与AI管理层 (Model and AI Management Layer)

负责AI模型的集成和管理：

- **模型管理器**：统一管理各种AI模型的调用
- **QwenAPI接口**：与通义千问大模型进行交互
- **CLIP处理器**：处理图像和文本的多模态嵌入
- **嵌入索引管理器**：管理向量数据的索引和检索

### 5. 应用层 (Application Layer)

提供各种应用接口和演示程序：

- **多模态演示**：展示系统的多模态处理能力
- **交互式主程序**：提供用户交互界面
- **测试程序**：验证各个模块的功能
- **初始化程序**：初始化系统和数据

## 数据流

系统中的数据流遵循以下路径：

### 基本流程
1. **数据采集**：从各种数据源捕获多模态数据
2. **数据预处理**：对捕获的数据进行预处理和格式化
3. **短期记忆存储**：将处理后的数据存储到 MessageMemory / MultimodalMemory
4. **向量生成**：为文本和图像数据生成向量表示（可选）
5. **索引构建**：构建向量索引以支持快速检索
6. **查询处理**：处理用户的查询请求
7. **上下文构建**：基于历史数据和当前查询构建上下文
8. **模型调用**：调用AI模型生成响应
9. **结果存储**：将结果存储到记忆系统中
10. **结果返回**：将结果返回给用户

### 记忆生成流程（关键流程）
1. **原材料收集**：MemoryGenerationManager 从 `message_memories` 和 `multimodal_memories` 表中收集未处理的数据
   - 消息：`processed=false` 的 MessageMemory
   - 多模态：根据时间或配置筛选 MultimodalMemory
2. **构建 MemorySource**：将消息内容 + 多模态描述(description)组合成文本来源
3. **分类判断**：MemoryClassifier 判断是否需要生成情景/语义/核心/程序/私密记忆
4. **记忆生成**：对应的 Generator（如 EpisodicMemoryGenerator）调用大模型生成长期记忆
5. **溯源记录**：将长期记忆与来源（message_id + multimodal_id）的关系写入 `memory_provenance` 表
6. **标记处理**：将已处理的 MessageMemory 标记为 `processed=true`

### 记忆溯源查询流程
1. 查询某条长期记忆（如情景记忆）
2. 通过 MemoryProvenance 表反查所有来源
3. 根据 `source_type` 和 `source_id` 获取原始消息或多模态数据
4. 展示证据链：“该记忆由哪些消息和多模态数据生成”

## 关键设计原则

### 1. 模块化设计
系统采用模块化设计，每个模块都有明确的职责和接口，便于维护和扩展。

### 2. 分层架构
采用分层架构设计，各层之间通过明确定义的接口进行通信，降低了系统的耦合度。

### 3. 数据一致性
通过事务管理器确保数据操作的原子性和一致性，防止数据不一致问题。

### 4. 可扩展性
系统设计考虑了可扩展性，可以方便地添加新的数据源、记忆类型和AI模型。

### 5. 性能优化
通过索引管理和缓存机制优化系统性能，提高数据检索和处理速度。
