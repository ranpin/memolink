# MIRIX多模态数据处理文档

## 1. 概述

MIRIX系统支持处理多种类型的多模态数据，包括图像、音频和屏幕截图。系统通过专门的模块来捕获、处理和存储这些数据，并将其集成到记忆系统中。

## 2. 数据类型支持

### 2.1 图像数据
- 来源：摄像头捕获
- 格式：JPEG
- 存储路径：captures/camera/
- 记忆类型：resource_memory表中的image类型

### 2.2 音频数据
- 来源：系统音频录制
- 格式：WAV
- 存储路径：captures/audio/
- 记忆类型：resource_memory表中的audio类型

### 2.3 屏幕截图数据
- 来源：屏幕捕获
- 格式：PNG
- 存储路径：captures/screen/
- 记忆类型：resource_memory表中的screenshot类型

## 3. 数据采集模块

### 3.1 摄像头捕获模块 (CameraCaptureManager)

#### 3.1.1 功能特性
- 支持单次图像捕获
- 支持持续图像捕获
- 使用OpenCV库实现
- 支持JPEG格式存储

#### 3.1.2 核心方法
- capture_image(): 捕获单张图像
- start_continuous_capture(): 开始持续捕获
- stop_continuous_capture(): 停止持续捕获
- store_capture_in_memory(): 存储到记忆系统

#### 3.1.3 配置参数
- 摄像头设备ID（默认为0）
- 图像分辨率（默认1280x720）
- 捕获间隔时间（秒）

### 3.2 音频捕获模块 (AudioCaptureManager)

#### 3.2.1 功能特性
- 支持单次音频录制
- 支持持续音频录制
- 使用PortAudio库实现
- 支持WAV格式存储

#### 3.2.2 核心方法
- start_audio_capture(): 开始音频录制
- stop_audio_capture(): 停止音频录制
- start_continuous_audio_capture(): 开始持续录制
- stop_continuous_audio_capture(): 停止持续录制
- store_audio_in_memory(): 存储到记忆系统

#### 3.2.3 配置参数
- 录制时长（秒）
- 录制间隔时间（秒）
- 采样率（默认44100Hz）
- 声道数（默认单声道）

### 3.3 屏幕活动跟踪模块 (ScreenActivityTracker)

#### 3.3.1 功能特性
- 支持单次屏幕截图
- 支持持续屏幕截图
- 使用ScreenCaptureKit和系统命令实现
- 支持PNG格式存储

#### 3.3.2 核心方法
- capture_screenshot(): 捕获屏幕截图
- start_continuous_screenshot(): 开始持续截图
- stop_continuous_screenshot(): 停止持续截图
- store_screenshot_in_memory(): 存储到记忆系统

#### 3.3.3 配置参数
- 截图间隔时间（秒）
- 截图质量参数

## 4. 数据处理流程

### 4.1 单次捕获流程
1. 用户触发捕获命令
2. 相应模块执行数据捕获
3. 数据保存到文件系统
4. 元数据存储到resource_memory表
5. 返回捕获结果给用户

### 4.2 持续捕获流程
1. 用户启动持续捕获
2. 系统启动后台线程
3. 按设定间隔自动捕获数据
4. 数据保存到文件系统
5. 元数据存储到resource_memory表

## 5. 多模态数据存储

### 5.1 存储策略
- 结构化元数据存储在SQLite数据库中
- 实际的大型文件存储在文件系统中
- 数据库中保存文件路径和关键元数据

### 5.2 元数据管理
每个资源文件都存储以下元数据：
- 文件名和路径
- 资源类型（图像/音频/屏幕截图）
- 文件大小
- 创建时间
- 内容摘要
- 标签和分类信息

### 5.3 文件组织
```
captures/
├── camera/          # 摄像头图像
│   ├── 2025-10-24/
│   │   ├── 12-00-00.jpg
│   │   └── 12-05-30.jpg
├── audio/           # 音频文件
│   ├── 2025-10-24/
│   │   ├── 12-00-00.wav
│   │   └── 12-10-00.wav
└── screen/          # 屏幕截图
    ├── 2025-10-24/
        ├── 12-00-00.png
        └── 12-01-00.png
```

## 6. 向量化处理

### 6.1 CLIP模型集成
- 使用CLIP模型为文本和图像生成向量表示
- 文本和图像向量维度：1024维（更新后的维度）
- 向量数据以二进制格式存储在数据库中

### 6.2 文本向量化
- 为对话内容生成向量表示
- 存储在recall_memory表的embedding字段中
- 支持文本相似性搜索

### 6.3 图像向量化
- 为图像资源生成向量表示
- 存储在resource_memory表的embedding字段中
- 支持图像内容相似性搜索

### 6.4 向量序列化
- 向量数据使用二进制格式序列化
- 支持float32类型的向量数据
- 提供序列化和反序列化接口

## 7. 多模态数据检索

### 7.1 传统查询
基于元数据的传统查询：
- 按用户ID查询
- 按时间范围查询
- 按资源类型查询
- 按标签和分类查询

### 7.2 向量相似性搜索
基于向量的相似性搜索：
- 文本到文本搜索
- 图像到图像搜索
- 文本到图像跨模态搜索
- 图像到文本跨模态搜索

### 7.3 混合检索
结合传统查询和向量搜索：
- 先进行元数据过滤
- 再进行向量相似性排序
- 综合评分排序结果

### 7.4 检索接口
```cpp
class VectorSearchManager {
public:
    // 混合搜索接口
    std::vector<SearchResult> hybrid_search(
        const std::string& query_text,
        int user_id,
        int limit = 10
    );
    
    // 向量搜索接口
    std::vector<SearchResult> vector_search(
        const std::vector<float>& query_vector,
        const std::string& memory_type,
        int user_id,
        int limit = 10
    );
};
```

## 8. 跨模态检索

### 8.1 实现原理
- 使用CLIP模型统一文本和图像的向量空间
- 文本和图像向量在同一空间中进行相似性计算
- 支持跨模态查询和检索

### 8.2 应用场景
- 用文本查询相关图像
- 用图像查询相关文本内容
- 多模态内容推荐
- 跨模态内容理解

### 8.3 查询示例
1. 用户输入文本："昨天我看到的那只猫"
2. 系统生成文本向量
3. 在图像资源中搜索相似向量
4. 返回最相关的图像资源
